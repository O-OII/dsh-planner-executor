# 模型接入与角色分配

[English](configuration.md) · [项目说明](../README.zh-CN.md) · [路由契约](ds-execution.zh-CN.md)

打开**设置 → 插件 → DSH 主从协作**。页面使用公共 `plugins.bundle.config` 插槽，不复制官方模型编辑器组件，不访问设置外壳的私有 store。缺少此插槽时，仍可独立使用浮窗。

## 1. 添加自定义 API 模型

![真实自定义 API 接入组件，公开合成数据](images/planner-model-setup-zh-CN.png)

*真实生产组件配合公开合成数据，不是私人 profile 或收费提供商验收。*

本页只创建**新提供商**，沿用官方模型编辑器的设置／凭据持久化接口，不修改已有提供商。目录提供商和高级编辑请使用**设置 → 模型 → 添加模型提供商**。当前 DSH 没有公共分区深链接；页面明确给出真实导航步骤，不模拟 DOM 点击。

1. 填写新的 **Provider ID**：小写字母开头，只用小写字母、数字和单连字符。已注册、已配置或属于休眠目录的 ID 均拒绝创建。
2. 选择 Host schema 支持的 **API 协议**。OpenAI Chat Completions／Responses 通常填写带 `/v1` 的 Base URL；Anthropic Messages 通常填写服务器根地址，因为 SDK 会追加 `/v1/messages`。以你的服务约定为准。仅接受 HTTP(S)，不接受 URL 账号密码、查询参数和片段。
3. 在遮罩只写字段填写可选 **API Key**。留空保留提供商原生认证，不代表已配置认证；不会把已存密钥读回浏览器。
4. 手填精确**模型 ID**，或明确点击**获取可用模型**后选择返回的行。发现操作通过 `llm.discoverModels` 请求端点，可能将草稿密钥发送到该端点，不是推理调用／连通性保证，不会自动写入。发现失败或缺服务仍可手填。
5. 按模型可选声明**推理档位**与 API 参数值。允许档位来自 Host schema，不猜测模型能力。只声明上游真实支持的能力；这里声明能力，不是默认执行器运行时强度。
6. 点击**创建提供商并保存凭据**，等待 Host 确认。成功会刷新模型选项；角色选择需要另行保存。

### 安全持久化与部分失败

- 需要 `llm-pi-ai` 命名空间、官方 schema 与 LLM 目录服务。非空密钥才要求凭据服务。只读 profile 禁用创建。
- 创建前重读提供商目录与 revision。一次 `settings.mutate("llm-pi-ai", [{op:"set",path:["providers",id],value:profile}], revision)` 只写**新** profile，不整表覆盖，不修改现用提供商，不开启路由。
- 非空密钥使用派生的 `PROVIDER_ID_API_KEY` 引用。`credentials.describe([ref])` 仅检查是否已配置／可写，不读取密钥值。引用已存在则拒绝，避免静默覆盖。
- 先设置、再 `credentials.set(ref,key)`，**不是原子事务**。profile 只保存 `apiKeyEnv`，不保存密钥。凭据阶段失败时保留已写 profile，清空输入；重新填写密钥后明确点击**仅重试 API Key**。会先确认 profile 未被改动，只重试凭据，不重复创建提供商。
- 冲突／拒写不自动重试。home／CLI 覆盖由 Host ConfigEditor 在写入时拒绝；描述符不能提前判断所有覆盖。重读元数据、检查官方模型页后再明确重试。
- 重连／卸载会清除密钥、作废旧请求结果。回执不完整时写入可能已经落地；再次创建前检查**设置 → 模型**。无法安全地承诺自动回滚外部写入。
- 提供商／凭据失败展示通用本地错误，不回显可能携带密钥的原始响应；无日志／localStorage 密钥存储。发现操作只在点击时执行，打开表单不会请求端点。

## 2. 分配角色

**主模型**是主会话的精确 provider/model 条件。目录选择保存 ID，不保存显示名称。**默认执行器**是一个已配置的 API 模型；可选运行时推理强度必须为精确目标支持。目录部分失败或不可用时仍可手填路由。

显式子 provider/model／推理选择与工具配置路由优先。DSH 允许且授权时，研究／测试可用原生显式选模；本插件**不按任务关键词猜测研究／测试路由**。worker 的深度／会话父关系会阻止向其追加规划者规则或再次自动路由，即使模型与主模型相同。

路由以完整 `{enabled,parentRoutes,targetRoute,locale}` 更新保存。关闭时可以保存空准备状态；开启前至少配置一个主模型条件与默认执行器。语法通过／保存成功不证明凭据、能力、价格或最终 API 可用。后续符合条件的新委派仍经 `llm.resolveCallConfig` 预检。

## 3. 语言、保存与同步

- 新安装默认简体中文，支持英文和跟随 DSH；保留已有明确偏好。Host 路由 `auto` 使用中文，浏览器跟随 DSH 使用 locale 服务。
- 面板语言、路由各有独立草稿／保存；提供商创建也独立，不是跨命名空间事务。切换页面可能卸载表单，离开前先保存／丢弃草稿。
- 只认 Host 回执展示开／关。关闭失败仍保留已确认的开启并报错；未知、加载、不可用不冒充关闭。
- revision 冲突保留角色草稿，要求明确审阅／丢弃，不重放旧意图。重连后旧回执无效，须重新核对 Host 真值。

参见[测试与验证边界](testing.md)。合成夹具和隔离官方 Settings 测试，不等于已安装 Host 的传输全链路、提供商连通性、收费推理或账单节省验收。
